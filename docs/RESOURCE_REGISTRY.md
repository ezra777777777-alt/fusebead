# 共享查重切换

本功能默认关闭。启动服务不会创建查重表，也不会挂载共享查重接口；仅设置接口密钥才挂载接口。网站与 Bot 接入前，必须完成独立审查和测试；真实数据库迁移、连接生产服务器及部署均须按仓库规则单独获得授权。

1. 准备恢复到隔离数据库的完整备份，核对网站项目编号、频道名和各频道历史清单。历史导出包含摘要和内部编号，应按内部业务数据保管；排除测试数据。网站历史频道别名需明确配置，不要猜测。
2. 在隔离数据库执行 `npm run build` 和 `npm run migrate:resource-registry`，再用历史清单执行 `node dist/resource-backfill.js --dry-run`。命令从标准输入读取 JSON 数组；默认也是预演。**预演会执行写入、最后回滚，期间持锁并阻塞网站投稿、审核和 Bot 登记**，因此只在隔离副本或所有写入暂停时运行。
3. 如果报告网站作品编号或 `local-dedup` 编号冲突，在隔离副本中定位对应的原始来源，确认哪些确实是同一资源、哪些只是错误别名，并由业务负责人决定保留或修正的历史记录。检查所有受影响渠道和已公开状态。不要自动删除、合并、改写原始数据，也不要把来源或内部清单发到群里。每次修正后重新导出并预演，直到无冲突；冲突未解决时不能启用。网站作品之间有真实重复时，须先在原系统按审批后的方案处理，再重新生成副本和清单。
4. 正式切换前停止所有旧版网站实例的投稿、修改、审核及 Bot 查重写入，备份并核对最新数据。在获得真实数据库迁移的单次授权后，执行迁移和最终回填 `node dist/resource-backfill.js --apply`。实际回填是一个事务，发生冲突会整批回滚；成功后会写入绑定项目和频道的持久完成标记。
5. 在写入仍暂停的状态下启用网站项目、频道、密钥及回填完成配置，启动新版本，并用授权的真实测试验证预查、投稿、跨频道重复拦截、错误恢复及看板回执。全部通过后再恢复写入。升级期间旧版本不遵守新事务锁，不能与回填或新版本写入并行。

回填完成后移除配置、改项目或频道会拒绝网站投稿、修改、放行和恢复，不能通过关闭开关绕过查重。配置恢复前不要强行清除完成标记；要更改绑定关系须先设计并审查完整的数据迁移。网站只按来源链接查重，Bot 的完整内容摘要是精确归一化匹配，不等同语义查重。网站预查不会占位，网站投稿时再次检查并登记；其他频道已登记的内容会被拒绝。

配置异常时仍可下架、撤回和退回；撤回或退回期间不会释放原查重登记，以免误放重复内容。配置恢复后，这些保留登记可能需要按历史冲突流程人工核对。
